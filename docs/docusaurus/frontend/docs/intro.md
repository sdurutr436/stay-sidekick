# SPA Angular — panel privado

Este sitio Docusaurus documenta el subproyecto [`frontend/`](https://github.com/sdurutr436/stay-sidekick/tree/main/frontend) de Stay Sidekick: la **aplicación de página única (SPA)** del panel privado, construida con **Angular 21** + **TypeScript**, servida bajo el prefijo `/menu/` detrás de nginx.

La API de componentes, servicios, guards y validadores se genera de forma automática con **TypeDoc** y se publica en el bloque "API (TypeDoc)" de la barra lateral.

## Visión general

| Pieza | Tecnología | Punto de entrada |
|-------|------------|------------------|
| Framework | [Angular 21](https://angular.dev/) (standalone components) | [`frontend/src/main.ts`](https://github.com/sdurutr436/stay-sidekick/blob/main/frontend/src/main.ts) |
| Builder | `@angular/build` con `inlineCritical: false` para CSP estricta | [`frontend/angular.json`](https://github.com/sdurutr436/stay-sidekick/blob/main/frontend/angular.json) |
| Estilos | SCSS compartido con `web/` (ITCSS + BEM) | [`frontend/src/styles/`](https://github.com/sdurutr436/stay-sidekick/tree/main/frontend/src/styles) |
| Tests | Vitest + cobertura Istanbul ≥ 90 % | [`frontend/vitest.config.ts`](https://github.com/sdurutr436/stay-sidekick/blob/main/frontend/vitest.config.ts) |
| Gestor de paquetes | pnpm 10 (corepack) | [`frontend/package.json`](https://github.com/sdurutr436/stay-sidekick/blob/main/frontend/package.json) |

## Estructura del subproyecto

```
frontend/
├── angular.json                # Build, serve y test (builder unit-test)
├── package.json                # Scripts ng + pnpm.onlyBuiltDependencies
├── vitest.config.ts            # Cobertura mínima 90% en sentencias, ramas, fns, líneas
├── Dockerfile                  # Multi-stage Node 20 → nginx:alpine, base-href=/menu/
└── src/
    ├── main.ts
    ├── app/
    │   ├── app.config.ts       # Providers (router, http, interceptors)
    │   ├── app.ts              # Root component standalone
    │   ├── components/         # Átomos, moléculas y organismos BEM
    │   ├── pages/              # Lazy chunks por ruta
    │   ├── services/           # Servicios inyectables (singleton)
    │   ├── guards/             # Guards de rutas (auth, rol)
    │   ├── interceptors/       # JWT, CSRF double-submit
    │   └── validators/         # Validadores reutilizables
    └── styles/                 # ITCSS compartido con web/
```

## Cómo se genera esta documentación

El script `prebuild` del [`package.json`](https://github.com/sdurutr436/stay-sidekick/blob/main/docs/docusaurus/frontend/package.json) ejecuta `typedoc` con la configuración de [`typedoc.json`](https://github.com/sdurutr436/stay-sidekick/blob/main/docs/docusaurus/frontend/typedoc.json):

1. TypeDoc recorre `../../../frontend/src` con `entryPointStrategy: "expand"`.
2. Usa el `tsconfig.typedoc.json` local (relajado: `skipErrorChecking: true`) para no fallar por decoradores de Angular que no se compilan aquí.
3. El plugin `typedoc-plugin-markdown` vuelca **Markdown** en `docs/api/`.
4. Docusaurus toma esos archivos por el sidebar `autogenerated` en `sidebars.js` y los sirve dentro de la categoría "API (TypeDoc)".

Como resultado: cualquier servicio, componente o validador con JSDoc en el código aparece publicado automáticamente al rebuild.
